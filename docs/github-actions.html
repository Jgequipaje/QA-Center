Overview

How it works

GitHub Actions runs automated tasks when something happens in your repo.

📥 Event
→
📄 Workflow
→
⚙️ Jobs
→
🧱 Steps
📥

Event

What triggers the workflow — push, pull request, manual click, or a schedule.

📄

Workflow

A .yml file inside .github/workflows/. One file = one workflow.

⚙️

Job

A group of steps that run on a machine (runner). Jobs run in parallel by default.

🧱

Step

A single command (run:) or a pre-built action (uses:).

Structure

Anatomy of a workflow file

Every workflow follows this structure. Comments explain each part.

name: My Workflow          # Name shown in GitHub Actions UI

on:                        # What triggers this workflow
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  my-job:                  # Job ID — used in needs: and branch protection
    name: My Job           # Display name (optional)
    runs-on: ubuntu-latest # Runner OS

    steps:
      - name: Checkout code
        uses: actions/checkout@v4   # Clone the repo

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: npm                # Cache node_modules for speed

      - name: Install dependencies
        run: npm ci

      - name: Run build
        run: npm run build
Triggers

on: — what starts your workflow

on:
  push:                          # Every push to these branches
    branches: [main, development]

  pull_request:                  # PR opened or updated
    branches: [main]

  workflow_dispatch:             # Manual trigger from GitHub UI

  schedule:
    - cron: "0 9 * * 1"         # Every Monday at 9am UTC
💡 Cron syntax: minute hour day month weekday. Use crontab.guru to build cron expressions.
Runners

runs-on: — where your job runs

Value OS Notes
ubuntu-latest Linux Fastest, most common, recommended default
windows-latest Windows Use when testing Windows-specific behavior
macos-latest macOS Slowest, use only when needed
Common Actions

uses: — pre-built steps

Actions are reusable steps from the GitHub Marketplace. These are the ones you'll use most. 

# Checkout your repo (always first)
- uses: actions/checkout@v4

# Setup Node.js with caching
- uses: actions/setup-node@v4
  with:
    node-version: lts/*
    cache: npm

# Upload files as artifacts (test reports, build output)
- uses: actions/upload-artifact@v4
  with:
    name: playwright-report
    path: playwright-report/
    retention-days: 30

# Download a previously uploaded artifact
- uses: actions/download-artifact@v4
  with:
    name: playwright-report
Jobs

Job dependencies with needs:

By default jobs run in parallel. Use needs: to chain them sequentially. 

jobs:
  lint:
    runs-on: ubuntu-latest
    steps: [...]

  build:
    needs: lint              # Only runs if lint passes
    runs-on: ubuntu-latest
    steps: [...]

  deploy:
    needs: [lint, build]     # Waits for both to pass
    runs-on: ubuntu-latest
    steps: [...]
⚠️ The job key (e.g. lint:) is what GitHub uses for branch protection status checks — not the name: field. Make sure they match what you add in Settings → Branches.
Environment & Secrets

Variables and secrets

jobs:
  my-job:
    runs-on: ubuntu-latest
    env:
      NODE_ENV: production        # Job-level env var

    steps:
      - name: Use a secret
        run: npm run deploy
        env:
          API_KEY: ${{ secrets.API_KEY }}   # From GitHub Secrets

Store secrets in GitHub → Settings → Secrets and variables → Actions. Never hardcode them in workflow files.

🔒 GitHub automatically masks secret values in logs — they'll appear as ***.
Conditionals

if: — run steps conditionally

# Always run (even if previous steps failed)
- name: Upload report
  if: always()
  uses: actions/upload-artifact@v4
  with:
    name: report
    path: report/

# Only on main branch
- name: Deploy
  if: github.ref == 'refs/heads/main'
  run: npm run deploy

# Only if something failed
- name: Notify on failure
  if: failure()
  run: echo "Something went wrong"
Background Processes

Running servers for E2E tests

Use & to run a process in the background, then wait-on to wait until it's ready. 

- name: Start dev server
  run: npm run dev &
  env:
    CI: true

- name: Wait for dev server
  run: npx wait-on http://localhost:5173 --timeout 30000

- name: Start API server
  run: npm run server &

- name: Wait for API server
  run: npx wait-on http://localhost:3333 --timeout 30000

- name: Run Playwright tests
  run: npx playwright test
💡 wait-on polls the URL until it responds or times out. Always set a timeout so the job doesn't hang forever.
Tips

Things worth knowing

⚡

npm ci vs npm install

Always use npm ci in CI. It's faster, uses the lockfile exactly, and fails if the lockfile is out of sync.

💾

Cache node_modules

Add cache: npm to setup-node to cache dependencies between runs. Saves 30–60s per job.

⏱️

Set timeout-minutes

Always set this on long-running jobs like Playwright. Prevents stuck workflows from eating your free minutes.

📊

Upload artifacts on failure

Use if: always() on artifact uploads so you get test reports even when tests fail.

🔓

Public repos = free

Public repos get unlimited Actions minutes. Private repos get 2,000 min/month on the free plan.

🔑

Job key = check name

Branch protection uses the job key (e.g. lint:), not the display name:. Keep them consistent.

Starter Templates

Copy-paste and go

1. Minimal CI (lint + build)

The simplest useful workflow — runs on every push and PR.

name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: npm
      - run: npm ci
      - run: npm run lint
      - run: npm run build

2. Full CI Pipeline (this project's setup)

Sequential jobs — each one only runs if the previous passes.

name: CI Pipeline

on:
  push:
    branches: [main, development]
  pull_request:
    branches: [main, development]

jobs:
  prettier:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: npm
      - run: npm ci --legacy-peer-deps
      - run: npx prettier --check .

  lint:
    needs: prettier
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: npm
      - run: npm ci --legacy-peer-deps
      - run: npm run lint

  typecheck:
    needs: lint
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: npm
      - run: npm ci --legacy-peer-deps
      - run: npm run typecheck

  build:
    needs: typecheck
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: npm
      - run: npm ci --legacy-peer-deps
      - run: npm run build

3. Playwright E2E

Starts both servers, waits for them, runs tests, uploads the report.

name: Playwright Tests

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  playwright:
    runs-on: ubuntu-latest
    timeout-minutes: 60
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: npm
      - run: npm ci --legacy-peer-deps
      - run: npx playwright install --with-deps
      - name: Start app
        run: npm run dev &
      - name: Wait for app
        run: npx wait-on http://localhost:5173 --timeout 30000
      - name: Start API server
        run: npm run server &
      - name: Wait for API server
        run: npx wait-on http://localhost:3333 --timeout 30000
      - run: npx playwright test
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: playwright-report
          path: playwright-report/
          retention-days: 30

4. Scheduled Nightly Run

Runs automatically every night at midnight UTC.

name: Nightly Tests

on:
  schedule:
    - cron: "0 0 * * *"

jobs:
  nightly:
    runs-on: ubuntu-latest
    timeout-minutes: 60
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: npm
      - run: npm ci
      - run: npx playwright install --with-deps
      - run: npx playwright test
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: nightly-report
          path: playwright-report/
          retention-days: 7
